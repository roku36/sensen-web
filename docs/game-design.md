# sensen ゲームデザインノート — スキルの所在

## スキルモデル

このゲームのプレイスキルは反射神経ではなく、以下の4軸に置く:

1. **テンポの所有** — 時間 (閃) は唯一の資源。いつ引き、いつ撃ち、いつ待つか。
   その全てがプレイヤーの意思決定であること
2. **読み** — 相手の公開キュー (確定済みの未来) から着弾時刻を読み、
   ブロックを減衰込みでジャストに合わせる
3. **コミットの呼吸** — 予約 (秘匿・可逆) と確定 (公開・不可逆) の往復。
   早いコミット = 連閃の勢い、遅いコミット = 柔軟性と情報秘匿
4. **精密合わせ** — 烈閃への解決着地、重カードの原子発火、熟成の使用窓

## 不変条件: 時間は常に閃単位の行動として消費される

**キューは決して空白にならない。** これはこのゲームの根本不変条件である。

理由 — 時間グリッドの保証: キューが常に埋まっている限り、すべての行動は
「現在のエントリの区切り = 閃境界」からしか始まらない。入力の 0.001 秒差は
次の閃境界に吸収され、反射神経は構造的に意味を持たない。もしキューに
空白を許すと、チェーンの開始点が入力フレームになり、最初に動いた一瞬の
差がその後の連続行動すべてに永続する — 反射神経ゲームへの退化。

実装上の要点: この不変条件は「予約が空なら埋める」ではなく **「キューが
空なら埋める」** と書かなければならない。予約が残っていても何も積めない
状況 (no-op ドローの大量消化が安全カウンタで打ち切られる等) が実在し、
条件を予約に紐づけていると、そこだけ 1閃 の空白が開いていた。

## 不変条件: 盤面の数値はすべて整数、時間の刻みはすべて閃 (2026-08)

HP・ブロック・筋力・毒は常に整数であり、**継続的に効くものはすべて閃
境界でだけ動く**。毒も焦土も常在型パワー (燃焼・金属化・残虐・悪魔の姿)
も同じ刻みで、「次の閃に7食らう」と読める盤面になる。

この規則は後から入れた。それ以前は StS 移植の名残で常在型パワーだけが
「毎秒レート × dt」を毎フレーム適用しており、整数の状態に端数を足す設計
だったため二つの実害が出ていた:

- **金属化が完全に無効だった。** ブロックは整数に丸められるので +0.05/frame
  は毎フレーム捨てられ、30閃 経ってもブロックは 0 のまま。カードが何も
  していないのに誰も気付かなかった
- **HP が小数化していた。** 193.50000000001 のような値になり、UI 側が
  `Math.round` と「|Δ| < 0.5 は無視」で誤魔化していた。丸め表示のため
  「HP 0 と表示されているのに生きている」状態も作れた

教訓として test/powers.test.ts は勝率ではなく効果そのものを assert する。
勝率ハーネスでは、完全に無効な金属化 (53%) と正常な金属化 (51%) を区別
できなかった — 2枚差し替えの勝率は「カードが何もしていない」という最大級
の不具合すら検出できない。

## 不変条件: 完全対称 (2026-06)

**両者は同一の閃グリッドを共有する。先手/後手は存在しない。**

旧仕様には「後手の半閃オフセット + 初期ブロック3」があったが撤廃した。
同一デッキ・同一入力はミラー状態を生み、同時致死は引き分けになる
(テストで固定済み)。これにより:

- 有利不利の補正という調整変数そのものが消える (補正は常に再調整の種)
- 両者の解決が同一閃境界に重なるのが常態になり、「同一境界の相互作用」
  (パリィ等) が設計空間として開く — docs/card-design.md の「拍」を参照

**同一境界の規則 — 回復が先、ダメージが後。** 同じ閃境界に重なった
イベントは、回復 → ダメージ (攻撃・焦土) の順で適用される。休息の回復は
同じ境界の焦土と正確に相殺できるが、すでに確定した致死をその後の回復が
覆す「同フレーム蘇生」は存在しない。
(この規則の必要性は対称化で露出したバグが教えた: 旧実装は max(0,hp−焦土)
クランプ → 同フレームの休息回復+1 で HP が 0↔1 を往復し、永遠に死ねな
かった。旧世界では半閃オフセットのせいで後手だけ回復が別フレームになり
「後手が必ず先に死ぬ」という非対称な形でこのバグが隠れていた。)

## 決定の経緯: 自動行動の設計 (2026-06)

旧仕様: キューと予約が空になると自動でドロー or 左端カード発動
(オートパイロット)。

- 問題 (a): 自動で「最善手風」の行動 (ドロー・カード発動) を打つため、
  無操作と下手な操作が上方補正され、スキル差が圧縮されていた
- 一度「自動行動の全廃」を試みたが即時 revert — 上記の時間グリッド
  不変条件を破壊し、行動開始タイミングの反射神経競争を生むため (問題 b)

**現行設計 — 「1枚ドロー、満杯なら休息」**: キューと予約が空になると、
シムが自動で「1枚ドロー」(1閃・連閃−1) を積む。手札が満杯か山+捨て札が
尽きていれば「休息」(1閃・HP+1回復・連閃リセット) を積む。

- 問題 (a) の解決: 自動行動は弱いが無意味ではない (補充 or 微回復)。
  攻めの判断は一切代行しない — スキル差は保存される
- 問題 (b) の解決: キューは常に埋まり、時間グリッドは途切れない
- 休息は防御的な選択肢としても機能する (攻めずに回復 vs 焦土の加速)。
  休息もキュー時間なので重カードの積みに算入される
- 予測は「無入力の未来 = 休息が積まれる未来」を正しく表示する
  (旧 predictMode の問題は『攻撃カードが勝手に予測に出る』ことだった。
  休息は中立なので予測に出るのが正しい)

## 予約の契約: 受理した予約は必ず発動する (2026-08)

「予約は失敗しない」はゲームの法だが、重カードの**積み要件**との組み合わせ
で破れていた。ゲートは予約時点の積み (先行予約の合計閃) を見て受理する
が、その積みは後から縮みうる — 予約済みドローは手札に空きがある間は 1閃、
埋まると 0閃 の no-op になり、手札から消えたカードの予約も 0閃 になる。

旧実装はこの「積み < 要件」を *"would only happen if the gate let through a
non-fireable plan"* と注記して `return false` していた。実際には到達し、
到達すると予約もキューも**永久に凍結**した (ランダム入力ファズで発見。
AI 同士の対戦でも 15戦で 594回 この状態に入っており、ラダーの測定値は
「どちらが自滅しにくいか」を測っていた — 修正後 lv4 vs lv3 は 29/30 から
19.5/30 になり、これが本当の実力差)。

同じ穴には**裏返しの症状**もあった。予約 [ドロー, 重撃] で手札が満杯だと
ドローは no-op として落とされ、重撃が積み0のまま先頭に立つ。発動条件は
「残り積み <= 要件」なので 0 <= 2閃 が素通りし、**積み2閃必要な重撃が
予告ゼロで即発動**していた。凍って撃てないか、予告なしで撃ててしまうか
— どちらも同じ原因 (積みは受理後に縮みうる) から出ている。

**現行の規則:** 積みが要件に足りないぶんは**既定行動で埋めてから**、
予約された行動を順に発動する。重カードは常に要件どおりの積み (相手が
読める予告) を持って発動し、プレイヤーは自分が約束した時間を払う。
埋めた既定行動はキューに休息/ドローとして表示されるので、予告は
見た目にも本物になる。

関連して「手詰まり負け」(使えるカードも空き枠もない) のルールは削除した。
キューが決して空にならなくなった時点で判定条件に到達不能となり、一度も
発火しない死んだルールだったため。該当プレイヤーは休息を積み続け、焦土で
決着する。
